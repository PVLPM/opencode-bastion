# OpenCode Bastion 1.1 — Native redesign, Agent Lanes, stability

Status: approved by owner via the v1.1 brief (2026-11-24). Supersedes the v1.0
design where they differ; everything else in `2026-11-24-bastion-v1-design.md`
still holds (read-only, one session family, host store as the only state).

## Card (three collapsed rows)

1. `[Agent] Session title ……… status mark` — capitalized agent name in a compact
   native composer-pill-like badge, then the stored session title (subagent
   suffix stripped, stable across follow-ups). Status mark on the right: the
   native dot-matrix activity glyph while running, native warning / critical /
   neutral marks otherwise, with accessible label and tooltip.
2. `Task • Activity` — task is the latest delegation description (orchestrator:
   first line of its latest user prompt); activity is the live, concise tool
   description. The separator only appears when both exist. Activity Ticker
   slides vertically on meaningful changes only.
3. `[logo] Model #Effort ……… duration cost context-ring lines chevron` — effort is
   the model variant actually used, never invented.

## Agent Lanes (replaces the bar timeline)

Data comes from the durable transcripts the host store already syncs:

- **Execution block** = first assistant turn after the previous `idle` message
  → the next `idle` message. Its status is the idle outcome. A session that is
  running has one open block extending to `now`; waiting applies only to it.
- **Gaps** are only between an `idle` marker and the next execution start —
  confirmed inactivity. Tool calls inside one execution never split it.
- **Handoffs** are the root transcript's `subagent` tool parts with a confirmed
  `metadata.sessionID`. A call lands on the child block running at the call
  time, else the next block to start. A second call to the same child is a
  follow-up. No child→child connectors, no inference from overlap.
- History is reconstructed from transcripts on reopen. Waiting intervals are not
  persisted by OpenCode, so past waiting is not drawn (documented limitation).

UI: one lane per session (orchestrator first, children by first start, stable
order), shared time axis with grid and markers, labelled blocks, dashed SVG
connectors above blocks, live extension, no forced auto-scroll when the user has
scrolled back. Region below the cards: collapsible, vertically resizable by a
drag handle, independently scrollable both ways.

## Stability

Root cause is established from host logs/source before any fix; the fix is the
smallest correction plus a regression test. No blanket catches or watchdogs.
